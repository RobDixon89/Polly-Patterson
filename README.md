# Storyblok test

An Astro site on Storyblok, with schemas in code, block adapters that map Storyblok fields to UI components, editable UI strings and a small SCSS design system.

## Setup

1. `pnpm install`
2. Copy `.env.example` to `.env` and fill it in (the access token is the space's **preview** token, so drafts load in
   the Visual Editor).
3. For the Visual Editor, the dev server needs HTTPS. Create a trusted certificate with
   [mkcert](https://github.com/FiloSottile/mkcert) and save it as `certs/localhost.crt` and `certs/localhost.pem`:
   `mkcert -install` then `mkcert -cert-file certs/localhost.crt -key-file certs/localhost.pem localhost`.
   Without them the dev server runs over HTTP; `DEV_HTTP=1` forces HTTP even with them (for tools that don't trust the
   certificate).
4. In Storyblok, set **Settings → Visual Editor → Location** to `https://localhost:4321/`.
5. `pnpm astro dev --background` (manage it with `astro dev stop | status | logs`).

## Scripts

| Script                            | Does                                                                                                        |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `pnpm cms:schema`                 | Compiles every `*.schema.ts` and regenerates the types in `src/cms/types/gen` (offline)                     |
| `pnpm cms:push [--space <id>]`    | Pushes the schemas to the space (needs `pnpm storyblok login` with a personal access token)                 |
| `pnpm cms:strings [--space <id>]` | Adds keys from `src/i18n/en_GB.json` to the `strings` datasource, removes deleted ones (never edits values) |
| `pnpm test`                       | Unit tests (`node --test`)                                                                                  |
| `pnpm check`                      | Type-checks the project (`astro check`)                                                                     |
| `pnpm storybook`                  | Storybook for the UI components; story images are in `public/img`                                           |

## Structure

```text
scripts/            cms-schema.ts (compile / push), cms-strings.ts (strings sync)
src/
  cms/
    storyblok.ts    API client and block registry (technical name → adapter)
    schema/         field builders (fields.ts), groups, allowed sections, schema types
    components/     <Name>Block/: <Name>Block.schema.ts + <Name>Block.astro (the adapter)
    utils/          field helpers (blocks.ts), story lookups (stories.ts), strings, dates
    types/gen/      generated by `pnpm cms:schema`; don't edit
  ui/
    components/     presentational components (props only, no fetching) and their stories
    types.ts        section themes, image and link models
  styles/           palette, type scale, theme and content-style mixins, fluid() and breakpoints
  i18n/             en_GB.json (default UI text) and the loader that merges the datasource over it
  layouts/          Layout.astro: head/SEO, header, footer, Visual Editor bridge
  pages/[...slug].astro   every page: the story at the same path
```

## Content model

| Story               | Content type      | Holds                                                                                                         |
| ------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------- |
| `home`, `about`, …  | `page`            | A Banner field (one `home_hero` or `inner_hero`) and a free area (`body`)                                     |
| `articles/` (start) | `article_listing` | Title, optional description and image for the inner hero; lists the folder's articles, 9 per page (`?page=2`) |
| `articles/<slug>`   | `article`         | Title, description, image, published date, external URL, free area (hidden when the external URL is set)      |
| `global/settings`   | `global_settings` | Header links, footer links, social URLs, copyright (`{year}` is replaced)                                     |

Every section and banner has `anchor_id`, `theme` (light / dark) and `background_image`, from `sectionFields()`. `SectionWrapper` fills the section with the background image (`object-fit: cover`, under a tint of the theme colour), cropped per device by `FULL_SCREEN_SOURCES` in `src/ui/devices.ts`. Rich text in the Rich Text
section offers H2–H6, bold, italic, quote, rule, links, lists and the H1–H6, Large, Default, Small and Extra small styles; banner
introductions use the reduced set (bold, italic, links, the body sizes).

**The code owns the schemas**: change a block in its `*.schema.ts`, run `pnpm cms:schema`, then `pnpm cms:push`.
Edits made in the Storyblok UI are overwritten by the next push.

### Adding a block

1. `src/cms/components/<Name>Block/<Name>Block.schema.ts` with `defineComponentSchema` and the builders in `fields.ts`.
2. Add it to `FREE_AREA_SECTIONS` (`src/cms/schema/sections.ts`) if editors place it.
3. `pnpm cms:schema`, then write `<Name>Block.astro` with the helpers in `utils/blocks.ts` and register it in
   `src/cms/storyblok.ts`.
4. `pnpm cms:push`.

### Strings

Fixed UI text (labels, `aria-label`s, empty states) is in `src/i18n/en_GB.json`. Components read it with
`Astro.locals.t('key')`. Editors change it in the `strings` datasource, which overrides the JSON within about a minute.
Add a key only when a component needs it, then run `pnpm cms:strings`.

## Styles

- In a rule, one-line `@include` statements (`@include body;`, `@include transition(color, 0.2s);`) come first, before
  any properties. Includes with a block (`@include hover-focus { … }`, `@include from($bp-tablet) { … }`) are nested
  rules and go after the properties.
- Every transition goes through `transition()` (`functions/_animate.scss`), so none run with reduced motion.
- Hover styles go through `hover-focus` (`functions/_media.scss`), so keyboard focus gets them too.
